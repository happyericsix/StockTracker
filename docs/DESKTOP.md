# 桌面版与分发形态设计（2026-10-22）

> 一句话：**服务器版服务家人（现在就能用），桌面安装包是产品方向（分阶段推进），手机端是桌面实例的远程窗口（后置）。最终用户只需要注册一家 LLM 供应商。**

本文档沉淀 2026-10-22 关于分发形态的全部架构决策。与 `ROADMAP.md` 的关系：ROADMAP 管"产品功能做什么"，本文档管"产品以什么形态交付给用户"。

---

## 0. 三种形态的定位

| 形态 | 状态 | 服务对象 | 数据位置 | 并发模型 |
|---|---|---|---|---|
| 服务器版（现有 docker 部署） | **运行中，家人可用** | 家人（≤5 人） | 服务器 MySQL | 单机单实例，够用 |
| 桌面版（安装包） | 设计定稿，分阶段实施 | 任何下载用户 | 用户电脑（SQLite） | N 份单用户应用，无共享瓶颈 |
| 手机端（PWA） | 后置，等桌面版落地 | 桌面版用户 | 不新增（远程窗口） | 同桌面实例 |

**决策依据：**

1. **家人规模够不着并发瓶颈。** 实测画像：2~5 人同时聊天无压力（聊天轮次并行、LLM 是网络 I/O）；重负载点在委员会决策（8 次串行 LLM 调用，240s）与全局工具池（4 worker/8 容量，满了返回 `tool_busy` 而非排队）。这是"降级"不是"卡死"。真正共享的是 LLM 日预算（全局、不按用户分）。
2. **桌面版的动机是数据主权叙事 + 用户自带 key（BYOK）= 零服务器成本**，顺带消解高并发与合规问题——不是"把服务器版做小"。
3. **ROADMAP §0.11"个人自用"的立场不变**：家人服务器版不是 SaaS 重启——注册关闭、账号手动创建、规模不扩张。公开注册的服务器版永远不做（见 §9）。

## 1. 家人服务器版：立即可用，全是配置级工作

上线清单（按优先级）：

1. **HTTPS**：`nginx-https.conf.example` + 域名 + Let's Encrypt。公网传密码的底线；iOS PWA 存储也要求安全上下文。
2. **关闭注册**：`AUTH_REGISTRATION_ENABLED=false`（当前默认 true = 对全网开放注册烧 LLM 额度）。家人账号手动创建发放。
3. **日预算认知**：`LLM_DAILY_TOKEN_BUDGET` 是全局共享；metering 账本（kind=usage 事件）有按用户数据，出现"一人吃光"再做按用户限额。
4. **备份认真跑**：MySQL 里是全家的记忆与交易记录。
5. **手机即用**：PWA 已完整配置（manifest/图标/竖屏/防串台缓存策略），浏览器打开 → 登录 → 添加到主屏幕，零开发。
6. 手机视图（四屏精选：行情/持仓/预警/快问 agent）是唯一开发项，可边用边迭代，不阻塞上线。

## 2. 桌面版总体架构

### 2.1 组件去向

| 现在（docker 5 容器） | 桌面版 | 说明 |
|---|---|---|
| MySQL | **SQLite 单文件** | 数据目录内，Flyway 迁移，用户零感知 |
| Redis | **删除 → Caffeine** | 见 §2.3 |
| nginx（serve 前端 + 代理） | **Java serve 静态 + SPA fallback** | 前端构建产物进 Spring Boot static；`baseURL:'/api/v1'` 相对路径 → 天然同源、零 CORS |
| .env 密钥 | **设置界面 → 配置文件** | key 建议进 OS 凭据库（Tauri keyring） |
| docker-compose | Tauri 安装包 | 用户双击安装，无 Docker |

**关键不变量**：Python agent 保持无状态、SQL 单一真相源——现有"Java/MySQL 真相源 + Python 无状态"分层是桌面化最大资产，架构不改。

### 2.2 数据目录与隐私边界

- 数据目录按 OS 规范（`%APPDATA%` / `~/Library/Application Support` / `~/.local/share`），**不进安装目录**（版本化更新布局会整体替换应用目录）。SQLite、chroma_data、.memory_index、.external_offload、模型、日志全在此。备份=复制目录；设置里配"导出我的数据"按钮。
- **出网清单（只有三条，写进产品页）**：① LLM API（用户自己的 key，记忆上下文随 prompt 发往用户自己账号）；② 行情/资讯公开数据源；③ 更新检查 latest.json（只传版本比对）。**没有任何用户数据流向我们的服务器**——服务器上只有静态安装包和更新清单。

### 2.3 缓存选型依据（为什么 Caffeine）

Redis 是"多进程共享的外置内存"，Caffeine 是"进程内自己的口袋"——选型与 web/桌面无关，只看**有几个进程要共享缓存**。桌面版单进程单用户 → 进程内缓存严格更优；现有 `TwoLevelCache`（本地+Redis）退化为单层即可。损失清单为空（唯一丢的是"重启缓存还热着"，缓存本义可重建）。服务器版单实例下 Redis 本就偏富裕，维持现状不动。

### 2.4 7×24 后台任务：补偿设计与诚实定位（2026-10-22 补）

**本质认知：7×24 = "有一台常开的机器"，与安装包形态无关。** 服务器版是我们出这台机器；桌面版把选择交回用户。丢的不是一个功能，是一份"谁来兜常开"的责任。

后台任务三分法与对策（进打包前置改造清单）：

| 类别 | 任务 | 桌面版命运 | 对策 |
|---|---|---|---|
| ① 结算/复盘类 | 15:30 结算、净值快照、周五复盘、情绪快照 | **结果零损失**（重头任务全在收盘后；`JobRun` 幂等补跑启动即补） | 验证补跑覆盖全部此类任务 |
| ② 盘中实时类 | 3s 行情流、10min 盘中关注 | 真丢失（机器关着=那几小时失明，实时无法回放） | 托盘常驻兜底 + 开机简报补偿 |
| ③ 凌晨维护类 | 03:40 资讯清理 | 永不触发（没人凌晨开机） | 改"启动时检查、超期即执行" |

三层缓解（按默认值设计，不做可选项）：

1. **托盘常驻 + 开机自启为安装默认**——装完即守护进程，用户日常开电脑 = agent 在线。
2. **任务补偿矩阵**：①类全部启动补跑；③类改启动检查。做完即恢复"结果层面 7×24"。
3. **开机简报（新功能）**：启动时主动生成"你不在的时候"——隔夜消息、盘中异动、错过预警的复盘。把"睡过了上午"从缺陷变成"回来第一眼有汇报"。纯增量开发，数据源全部现成。

**真要 100% 7×24 的明码标价**：日常电脑托盘（零成本，覆盖开机时段）/ 小主机·NAS 服务模式（真 7×24，电费）/ 云 VPS 自部署（真 7×24 + 免维护，每月几十元）。家人继续用服务器版 = 我们替他们提供常开机器。**产品终局：双形态并存——服务器版（常开旗舰）+ 桌面版（数据主权）。**

## 3. LLM 供应商体系（多供应商 BYOK）

**现状（2026-10-22 起）**：chat = DeepSeek（必选）+ 可选任意 OpenAI 兼容 fallback（重试/冷却/切换机制已有）；embedding = 通用 OpenAI 兼容三变量（`EMBEDDING_API_KEY/BASE_URL/MODEL` 配齐才启用，否则安静退化关键词检索）。**智谱硬编码已全部移除**（代码、.env.example、.env 迁移至通用变量，测试全绿）。

**设计：**

1. **懒读取重构**：`llm_service` 从 import 时读全局 env 改为每次调用现读配置（`embeddings._config()` 同款模式），配置源=设置界面落库的配置文件，env 仅开发兜底。
2. **供应商能力位**泛化三处 DeepSeek 专属行为：`reasoning_effort` 注入只对支持的端点发；委员会深度模型改为每供应商可选配（未配回退主模型）；`response_format` 剥除重试兜底已有，直接复用。
3. **设置界面**（Cherry Studio 模式）：预设供应商（DeepSeek/OpenAI/硅基流动/Moonshot/自定义）+ 填 key + 选模型 + **测试连接**（最小请求验证）；主备顺序用户可拖。
4. **海外供应商网络可达性用户自理**，自定义 base URL 栏位覆盖代理场景；非 DeepSeek 供应商先标"实验性支持"（DeepSeek 是深度调过的基准：reasoner 路由、503 退避皆按其实测）。
5. **桌面版 embedding 规划**：本地 ONNX 小模型（bge-small-zh 级，CPU 毫秒级），`EMBEDDING_BACKEND=local` 分支，接口不变只换实现；fail-open 兜底已在，模型损坏退关键词检索。落地后用户出网只剩两条。

## 4. 打包流水线

**入场券（前置改造，不做完打包=白打）**：① SQLite+Flyway（V1 基线、`ddl-auto=validate`、`desktop` profile 同份代码双数据源）② Caffeine ③ 配置文件化。验收=一台没装 JDK/Python/MySQL 的干净 Windows 上全功能可跑。

**五步流水线：**

1. 前端 `vite build --mode desktop`（关 PWA——service worker 缓存旧 index.html 会导致更新白屏）→ 产物进 jar static。
2. Java：`mvnw package` fat jar + `jlink` 裁剪 JRE（jdeps 分析，~40-60MB）。
3. Python：PyInstaller `--onedir`；**先瘦身**——chromadb（numpy 后端兜底已有）、mlflow（仅训练用）从运行时排除；pandas/numpy/akshare 保留（体积大头）；带 `prompts/`、`_ths_crypto_shim` 数据文件；模型按体积定打包或首启下载。
4. 组装版本目录：`apps/1.0.0/{runtime/, app.jar, py/}`，用户数据目录在外。
5. Tauri 壳（开窗/托盘/随机端口/自动内部 token/健康检查拉起 Java→Python）+ bundler 出 NSIS 安装包（中文、图标、许可页）。

**签名（两把别混）**：Windows 代码签名证书（OV 级，解决 SmartScreen/Defender 对 PyInstaller 误报，可后置购买）vs Tauri updater 的 minisign 密钥对（自动更新防篡改，免费自生成，上线必须）。

**分发与构建**：安装包与 `latest.json` 同目录（nginx `location /dl/`，量大挪 OSS 只换链接）；`latest.json` 同时是下载页版本显示与应用内更新检查的数据源，一次构建两处产出；一键 `build.ps1`（前端→jar+jlink→PyInstaller→组装→tauri build→包+清单），单人项目先不上 CI。**发版验收=干净虚拟机全流程**。

## 5. 版本与更新

- **原子版本号**：壳/前端/Java/Python/模型绑定为一个版本，绝不混装（Java↔Python 内部 REST 契约不跨版本）。
- **更新机制**：`latest.json` 清单（版本/地址/签名/说明/`min-supported-version`）→ 后台下载 → 签名校验 → 下次启动切换；**版本化目录+指针原子切换**（`apps/1.2.0`、`apps/1.3.0` 并存），失败回滚，绝不原地覆盖。
- **数据迁移是难点**：Flyway 按序 SQL；**迁移前自动备份 DB**；DB 写版本戳防旧版应用开新库。
- **强制更新门**：低于 min-supported-version 强制更新（LLM 供应商协议变更、安全修复时用）。
- **灰度**：清单按比例放量；版本上报可关闭。
- **测试纪律**：每次发版测"从上上版带真实数据升级"的路径，不只测全新安装——桌面应用事故几乎都在迁移上。

## 6. 下载页

使命：60 秒内让陌生人明白是什么、为什么装、点下载。**独立纯静态页**（不进主前端构建，独立部署独立更新），nginx `location /download` 或独立子域，视觉沿用墨阶（`DESIGN.md`）。

结构：Hero（一句话主张 + 主下载按钮 + **版本行与 latest.json 同源** + "还没有 key？3 分钟申请教程"前置）→ 三步上手（安装→填 key→开始用，配首启向导截图）→ 特性×3~4（隐私本地是差异化卖点放首屏）→ 系统要求 → FAQ（key 申请含费用/数据在哪/怎么更新）→ 更新日志 → 页脚（隐私声明=§2.2 出网清单直译 + 备案号，备案进行中）。

按钮做 OS 检测高亮；一个主 CTA。**先上预告版占位（特性+保持关注），安装包就绪点亮按钮**，结构不变。文案与"申请 key 教程"先行打磨（教程与首启向导共用素材）。

## 7. 手机端（后置，等桌面版落地）

**定位：桌面实例的远程窗口，不是独立应用。** 架构里不存在数据同步——手机是同一实例的另一窗口，换手机装 PWA 登录即全量数据。手机=配件，桌面=本体。

分三步，每步验证下一步：

- **V0（零开发）**：同 Wi-Fi / Tailscale 组网 → 手机浏览器打开实例地址 → 添加到主屏幕。验证需求真实性。
- **V1（1~2 周）**：手机四屏精选视图 + **预警 webhook 外发**（POST 到 Server酱/企业微信/飞书 bot，桌面手机双受益，一天量级，手机端唯一"不做就缺核心价值"的模块）+ 回前台自动恢复（visibilitychange + EventSource 已有重连）。
- **V2（产品化）**：安全暴露 + 设备配对码 + HTTPS。组网方案：**Tailscale 推荐**（WireGuard 点对点、零公网 IP、路由器零端口、免费档 6 用户设备不限）；国内坑=官方 DERP 境外，打洞失败走中继延迟高 → 自建国内 DERP（1C1G 云主机 20ms 级，免备案方案社区成熟）/Headscale 自托管是重度用户兜底。**服务只绑 Tailscale 网卡 IP** 加固。进阶：Java 绑定地址默认仍 127.0.0.1，显式开启远程才绑出。

**两个硬前提：**
1. **服务模式（headless）**：GUI 应用无法在无人登录时运行，须提供注册为系统服务（Windows Service/launchd/systemd）的无窗形态——"电脑当服务器"和"手机一直能看"的技术前提，复用桌面版组件非第二产品。
2. **推送现实**：iOS PWA 后台推送受限 + 国产 Android 无 GMS → 秒级推送需原生壳+厂商通道（V3，需求验证后再做）；V1 的 webhook 外发是正解。

**两条守则（今天就生效，防未来埋雷）**：前端不 fork"桌面专用版"（mode 区分构建即可）；API 不假设单客户端（ChatService 轮次簿记"新轮取消旧轮"按用户记账——手机发起会掐断桌面在跑的轮，需按设备维度或 UI 明示）。

## 9. 明确不做（本设计的克制清单）

| 不做 | 原因 |
|---|---|
| 公开注册的服务器版 / 多租户 SaaS | 家人版注册永远关闭；公开部署先过合规（ROADMAP Phase 5D） |
| 多实例水平扩展（ShedLock / SSE 总线 / 分布式 epoch） | 单机家人规模够不着；为不存在的流量上分布式是负收益 |
| 桌面版带 MySQL/Redis/Docker | 用户零配置是铁律；嵌入式 SQLite + 进程内缓存是唯一形态 |
| 手机端原生 App / 秒级推送 | V0~V2 验证需求后再说；webhook 外发已覆盖 80% 场景 |
| 智谱或任何单一供应商硬编码 | 已移除（2026-10-22）；供应商永远走通用 OpenAI 兼容配置 |
| 把 key 打包进应用 / 云端 key 代理 | key 发出去=送额度；代理=token 钱仍是我们出，且涉收费合规 |
